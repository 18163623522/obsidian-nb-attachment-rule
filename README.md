# 笔记白板附件规则 (nb-attachment-rule)

一个 Obsidian 插件，为「笔记 / 白板」双目录结构定制附件的**存放规则**与**排序规则**。

## 解决什么问题

如果你的库采用类似下面的结构（笔记和白板分开、附件统一放在各自文件夹下的 `附件` 里，再按所属文件名建子文件夹）：

```
某主题/
├── 笔记/
│   ├── 分类A/
│   │   └── 某篇笔记.md
│   └── 附件/
│       └── 某篇笔记/
│           └── 截图.png
└── 白板/
    ├── 某个白板.canvas
    └── 附件/
        └── 某个白板/
            └── 截图.png
```

那么你会遇到两个原生解决不了的问题：

1. **附件放不对地方** —— Obsidian 原生的附件位置设置是全局静态的，无法按「当前编辑的是笔记还是白板」分流到各自的 `附件/<文件名>/`；
2. **附件文件夹排不在最后** —— 原生只能按名称排序，`附件` 这种中文名永远夹在中间。

本插件同时解决这两件事。

## 功能

### 1. 附件放置规则

- 在 `笔记` 文件夹下（含任意深度的子分类）的 `.md` 中**粘贴或拖入**附件 → 自动存入 `笔记/附件/<该笔记名>/`
- 在 `白板` 文件夹下的 `.canvas` 中粘贴/拖入附件 → 自动存入 `白板/附件/<该白板名>/`
- 目标路径中的缺失层级会自动创建，重名文件自动追加序号
- 当前文件不在 `笔记` / `白板` 祖先之下时，回落到 Obsidian 原生附件位置设置，不会误放

### 2. 附件文件夹置底

文件管理器中，名为 `附件` 的文件夹固定排在所在文件夹列表的**最后**（含排在文件之后），可在设置中关闭。

### 3. 粘贴图片自动重命名

新粘贴/拖入的图片按模板自动重命名（默认 `file-<17位时间戳>`，如 `file-20261027164706032.png`），与 [Custom Attachment Location](https://github.com/RainCat1998/obsidian-custom-attachment-location) 的重命名规则一致：

- 重命名通过 `fileManager.renameFile` 完成，Obsidian 会自动更新笔记与白板中所有引用链接
- 只处理「核心粘贴流程生成的名字」（如 `Pasted image xxx`、`粘贴的图像`、`截屏` 等），自己命名的图片不会被改动
- 重名时按设置的分隔符追加序号

## 安装

### 方式一：手动安装

下载 `main.js` 与 `manifest.json`，放入：

```
<你的库>/.obsidian/plugins/nb-attachment-rule/
```

然后在 设置 → 第三方插件 中刷新并启用。

### 方式二：BRAT

安装 [BRAT](https://github.com/TfTHacker/obsidian42-brat) 插件后，添加本仓库地址即可。

## 设置

| 设置项 | 默认值 | 说明 |
|---|---|---|
| 接管附件存放位置 | 开启 | v1.2.0 新增。关闭后完全不干预附件路径，使用 Obsidian 官方设置（重命名与置底功能不受影响） |
| 笔记文件夹名 | `笔记` | md 笔记所在的祖先文件夹名 |
| 白板文件夹名 | `白板` | canvas 白板所在的祖先文件夹名 |
| 附件文件夹名 | `附件` | 附件统一存放的子文件夹名 |
| 附件文件夹置底 | 开启 | 文件管理器中 `附件` 文件夹固定排最后 |
| 粘贴图片自动重命名 | 开启 | 粘贴/拖入的图片按模板重命名 |
| 重命名模板 | `file-${date}` | 支持 `${date}`（17 位时间戳）与 `${name}`（原文件名） |
| 重名分隔符 | 空格 | 模板重名时追加的分隔符 |

三个文件夹名都可以改成你自己的目录约定，无需改代码。

## 工作原理

- **放置规则**：接管 Obsidian 保存附件时读取的 `attachmentFolderPath` 配置，在粘贴/拖入的瞬间按当前活动文件的类型（md / canvas）与其所在祖先文件夹动态计算目标路径。对 Obsidian 的 canvas 原生粘贴流程同样生效。
- **置底**：接管文件管理器的 `getSortedFolderItems` 排序函数，把 `附件` 文件夹移到返回列表末尾。该函数属于 Obsidian 内部接口，若未来版本变动，本功能只会在控制台提示并自动停用，不影响放置规则。

## 注意

- v1.1.0 起已内置 Custom Attachment Location 的重命名规则，**可直接用本插件完全替换它**（启用本插件后关闭该插件即可），避免两个插件互相抢路径。
- 本插件只改变「新粘贴/拖入附件」的去向与名字，不会移动或重命名已有附件。
